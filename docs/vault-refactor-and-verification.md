# 既有知识库重构与分层验收

旧知识库重构的目标是让知识可以检索、核对和复用。先纠错、保留必要知识和证据，再压缩重复表达。

## 完整流程

1. 明确主库、来源与写入范围，读当前工作约定、状态和交接；不同副本先比较新增、修改与冲突。
2. 从实际文件建立全量清单，检查链接、标题与块锚点、附件、重复、题答配对和导航。短文件名存在多个候选时列歧义；孤儿附件先待核。
3. 按概念、题目或完整来源小节建逐项台账。对照原题/原图后再推导或验算，写出定义、变量、单位、条件、反例与图示方向。
4. 已核问题同步权威正文与引用副本；等价内容回链，互补来源记录贡献，冲突保留具体条件分支。好笔记没有改进理由就保持原文。
5. 修改前备份本批文件，固定旧路径映射，增量迁移后读回。遇到其他写入或文件漂移时先协调，不覆盖。
6. 每批检查变更，阶段末检查当前全库结构，逐项汇总专业复核范围。公开发布通用流程与自编范例，个人来源留在本机。

## 验证层不能互相替代

| 实际证据 | 支持的结论 | 尚不支持 |
|---|---|---|
| 来源清单 | 指定范围有哪些材料 | 已通读、已纠错 |
| 文件、链接和附件检查 | 检查范围内可解析 | 指向同一概念、裁图完整 |
| 公式语法/排版检查 | 解析器接受、页面满足规则 | 数学或学科语义正确 |
| 原页、原图核对 | 指定条目对源成立 | 未核条目和整书终审 |
| 推导、验算与条件复核 | 指定条目专业内容已核 | 全部学科内容正确 |
| 客户端实际使用 | 抽验页面与点击可用 | 所有客户端和页面可用 |
| 本机运行、仿真、硬件 | 指定环境与条件下的观察 | 未测环境和设备结果 |
| 远端提交与 CI | 提交可读、工作流检查通过 | 私人库的全部语义已审 |

自检和独立复核分别记录。已见旧答案的回归核查注明上下文；抽样不升级为全量。报告列实际分母、时间、已核定、已修正、待补证、未审查和证据指针。

## 最小台账

每项记录 ID、权威文件、来源位置、本次动作、原问题、判据/验算、实际复核范围、未解决事项和日期。推导在正文、计算在计算记录，台账引用证据。完成度从台账汇总，避免在多份报告复制数量。

方法记录至少回答：什么情况下适用，按什么步骤做，什么证据证明结果，哪里尚未验证。项目快照与具体经历放复盘记录，通用方法只保留有复用价值的条件和步骤。

## GitHub 发布

沿用目标仓库可见性，使用允许清单暂存，只提交通用流程、检查脚本、自编测试与可公开范例。原始会话、个人笔记、教材/课件、作答、凭据和账号配置不进入公开版本。发布前检查 staged diff，发布后核对实际远端提交；远端可读和 CI 分别报告。

本页是流程说明，不宣称完成任何私人知识库的全量语义验收。具体工具能力与历史实测范围仍以[验证记录](validation.md)为准。
