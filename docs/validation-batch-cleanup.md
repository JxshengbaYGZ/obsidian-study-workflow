# 批量清理类任务的验收

本页是一节补充稿，建议并入 [验证范围与证据等级](validation.md) 的“验收分层”之后。批量清理指“成百上千个文件按规则删除图片、替换句子、改链接”这类任务：它的风险不是单张卡写错，而是范围没扫全、变体没处理、删完后结构断掉。

## 与单卡验收的区别

单卡验收看“这张卡的内容是否对”；批量清理要同时看四件事：

- 范围：清单里的文件是否就是实际改动的文件，有没有漏网或误伤。
- 一致性：同一类结构是否被替换成同一个模板，有没有几种写法并存。
- 完整性：删掉图片或句子后，卡片的来源、链接、结构是否仍然成立。
- 残留：目标图片、旧话术、旧模板是否真的为 0，还是只是“主要部分”为 0。

因此批量任务不能只按“内容是否正确”验收，必须增加静态层与结构层。两项被验收任务的判定规范见[知识卡与题卡的图文去冗余](card-redundancy-cleanup.md)与[整理过程话术的清理分层](editorial-phrase-cleanup.md)。

## 验收分层

| 层级 | 能否自动 | 具体做法 | 结论强度 |
|---|---|---|---|
| 1. 静态检查 | 自动 | 全库扫描：图片嵌入目标是否存在、wiki 链接是否可解析（含 `#锚点`、`|别名`、相对路径、`.md` 后缀）、frontmatter 是否完整未闭合、PDF 页锚点格式 | 只证明引用不断，不证明内容对 |
| 2. 清单一致性 | 自动 | 修改清单行数 = 实际改动文件数；每轮替换未匹配数 = 0；目标图片残留数 = 0；旧模板句残留数 = 0；改前备份可回滚 | 证明“该改的都改了” |
| 3. 结构检查 | 自动 | 按卡类型断言必需结构：需要局部图的题卡有“原题图 + 局部图 + PDF 页链接”，无图题卡有“原题来源 + 完整题干说明 + 无图片”，保留整页图的卡有说明理由 | 证明结构统一 |
| 4. 抽样内容复核 | 半自动 + 人工 | 每类抽 3–5 张完整卡片：删图卡看文字是否完整；裁图卡看图是否必要；保留整页卡看理由是否写清；链接卡看跳转目标是否指向正确页 | 抽样有效，不外推全量 |
| 5. 原页核对 | 人工 | 局部图与原页对照：题号、选项、相邻小问条件、图注没有被切掉；同一题跨多页时逐页看 | 只覆盖核验过的图 |
| 6. 客户端目视 | 人工 | Obsidian 阅读模式：图片显示、链接跳转、折叠块展开、表格渲染 | 只证明阅读侧可用 |

每层独立记录“做了/没做、覆盖多少、结论是什么”，下一层不能自动继承上一层的结论。

## 必须自动化的检查

这些检查用脚本跑，结果写进验收记录。链接、锚点与附件存在性可直接用仓库已有的只读审计工具 `scripts/audit_vault.py`（见 [只读结构审计工具](vault-audit.md)），本页不重复它的清单：

- 图片嵌入：`![[...]]` 的目标文件是否存在；删除嵌入后是否留下空行或空折叠块。
- wiki 链接：目标是否存在（候选解析：原路径、原路径 + `.md`）；改名小节锚点后要全库回查旧锚点。
- frontmatter：必备字段、YAML 闭合、状态词是否还有被清理的批次前缀。
- 残留：遗留的目标图片路径、旧说明句、旧模板句、目标话术词。
- 结构：按卡类型断言标题与必需块（见上表第 3 层）。
- 计数：修改清单与实际改动文件对齐（没有 git 时用备份目录比对）。

## 报告口径

- 写“静态检查通过、清单一致、抽样 5 张”——不要写成“全库已验收”。
- 未做的层级写“未做”，例如“客户端目视：未做”。
- 已知限制单列：刻意保留的整页图、未重裁的图、链接改动后仍需人工点开的卡、只能人工判断的裁图边界。
- 批量任务的“完成”只表示修改已执行、静态检查通过；它不等于内容正确，也不等于原页已核对。

## 案例口径（2026-10 批次）

- 删整页图任务：目标整页图残留 0、旧说明句残留 0、5 张需图卡的“原题图 + 局部图 + PDF 链接”结构全部符合；22 张保留整页图的卡保留说明理由，作为已知限制。
- 话术清理任务：全库（排除记录文件）残留词命中为 0；剩余命中逐条记为合法保留并写理由。
- 大学物理 18 题：结构断言 18/18（7 张有原题原图、11 张无图有来源说明）；18 个题框的坐标框核验与联系表目视属人工；全量语义复核未做。
- 以上都只支撑“修改已执行、结构一致”，不支撑“全部知识卡内容正确”。

## 隐私边界

验收记录中的真实路径、页码台账、逐卡清单留在使用者本机，不回填公开文档；本页只保留检查口径与可复述的层级定义。
