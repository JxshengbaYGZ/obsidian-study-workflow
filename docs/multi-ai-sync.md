# 多 AI 同步同一套笔记规则

统一正文为 `skills/study-knowledge-base/references/note-standard.md`。每个 AI 的入口都指向同一版本，避免各自保存不同的编写准则。

## 更新已有安装

1. 查明实际使用的全局指令、工作区指令与技能目录，核对已有调用路径；不能仅凭常见目录名认定客户端会读取。
2. 备份待改文件并记录原始哈希。保留无关的用户偏好、人格、权限和项目规则。
3. 将仓库的 `skills/study-knowledge-base` 整个目录复制到确认有效的技能目录。已有 `complete-study-notes` 时一并更新为本仓库的兼容入口，使两个目录保持并列。
4. 对没有已确认技能加载机制的客户端，保留可读取的本地仓库，在其已确认的指令文件中写入版本、正文绝对路径与简短摘要；不要假设创建一个 skills 文件夹就能生效。
5. 合并或替换旧的笔记规范段落。旧任务状态作为历史保留，但不再承担当前编写标准；不能只在末尾追加一段新要求。
6. 写入前再次核对目标未被其他进程修改，写后比较目标内容与来源文件，检查入口链接能到达正文。

简短入口可写成：

```text
笔记整理准则版本：2026-11-10。
开始笔记编写、重构或复核前，读取 <统一正文的实际绝对路径>。
新概念先解释，同类对象分别讲完整，再横向比较；常见情形先行。
保全有效知识，关键推导不断步，公式带条件；不新增自编题或自测。
知识标题无装饰序号；适合时用加粗核心句和缩进的常规说明，并列性质分行列出；清晰流程图直接引用并给读图重点。
实际显示与专业审读分别验收。
本段替代旧的固定栏目、强制短例及自测规则，仅适用于笔记任务。
```

## 生效怎样确认

文件回读一致只证明安装内容一致。已有会话可能仍持有旧上下文；新会话或明确重读后，观察是否实际读取此版本，才记录“已加载”。再用真实的笔记请求检查行为，才能记录“执行已验收”。

不擅自重启客户端、打断运行任务或发送消息来制造加载证明。具体安装位置、备份和各端状态留在私有同步清单；公开仓库不保存用户机器路径或私人配置。
