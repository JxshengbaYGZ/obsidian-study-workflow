# 无历史上下文的执行约定

## 输入与默认值

必需：可访问的材料、可写输出位置，以及能读取相应格式的工具。用户已给过的信息直接沿用。未指定目录时在当前可写工作区建立 knowledge-base；默认 Markdown、保留原文件、沿用已有风格。只有实际无法读取、目标冲突或专业内容无法判定时提出具体问题。

检查 PDF 是否有文字层；扫描页必须实际看图，不能把 OCR 输出当原稿。字幕缺板书时标明缺口；图表、电路、几何关系是题干的一部分，保留图并转写关键连接、方向和标注。没有相应工具时不假称完成识别。

## 最少维护记录

- **state.md**：目标、来源页数及已读/未读/待补证范围、知识点提纲、已改文件、下一步。小项目放一处；只有太长时再拆sources/outline，已有分文件无需迁移。日志、逐题证据不复制到这里。
- **ledger.json**：条目状态、源位置和证据指针；详细推导保留在题卡，程序计算保留在计算记录，台账只引用这些位置。阶段报告从台账汇总，不再手写多份相同报告。

逐项审查台账另按记录规则保存；示例 expected_ids 必须从实际清单导出或人工核对，不能只列已经处理的项目。

## 小批执行

横向试跑启动时固定一份最小交付清单：题卡、知识点（可明确复用）、关系链接、实际嵌入的完整原图、来源及检查。用户省略总结或上传不等于省略这些内容。复用缓存须指出当前有效版本；历史审查否决的裁图不可因文件存在而复用。含旧答案或纠错历史的上下文注明“已见答案回归”，不能称盲测。对比仅使用交付范围一致且有实际计时的数据；没有起止记录、token接口则填null。

保存简短检查结果（命令、退出码、检查数量和错误）；空输出不支持“公式渲染通过”。检查生成公式列表后由脚本读取，避免把带美元符号的数学正则内嵌到会展开变量的命令字符串中。

先完成一个知识点及一题的全链路；无题目材料可自编一题并标注来源身份。首次小样自行检查，除非用户要求验收，不以等待确认阻断已授权范围。

按完整来源页和上下文容量成批：同页短题一并处理，跨页题读全；长证明缩小批量。不固定为三题，也不因处理批结束而停止用户授权的整卷/章节任务。项目原有明确批量约束继续遵守。先核源、求解、自检、落盘，继续下一批。

独立复核集中在阶段末（一份卷、一个章节或用户指定范围），对该阶段逐项覆盖后统一同步。同步前建立本批附件清单：每张题卡引用的原题裁图、原作答裁图等二进制文件，都要逐个确认已复制到 vault 的实际路径；同步后再读回 Markdown，并检查这些附件存在且文件非空。题干无法确定或同类错误可能扩散时，暂停该条目/类型，其他内容继续。处理批次不等于复核阶段；自检必须随写随做，不能积累已知错误到最后。

概念：定义/条件/方法/关联题/来源。题卡：完整题干/解答/方法与易错/实际原图/关系链接。技巧：来源支持的具体动作、条件、边界、可复算短例及去重理由。没独立技巧不凑卡。

## 低重复原则

- 公式提取→渲染、写文件→验收等有依赖的步骤顺序执行；仅独立操作并行。每次重新裁图后实际查看最终图，来源同时记录PDF物理页和卷面页。模糊题逐字符保留不确定性，不只标最明显的遮挡；检查器须覆盖实际使用的链接语法。

- 本地 vault 已落盘时默认直接读回验收，不再逐文件 PUT 同一内容。只有远端目标或已证实的刷新需求才用 API；失败保存具体操作、耗时和错误，最多一次重试后保留本地成果。没有调用日志不得归因为“API 卡住”。
- 本批用一份相对路径 JSON 清单调用 `scripts/check_delivery.py ROOT MANIFEST`，一次检查变更文件及 wiki 链接/附件；它不验证裁图边界、标题锚点或数学语义。裁图必须实际看最终裁图，确认题干首行、矩阵上下边、末项和原作答都保留；文件非空不等于完整。
- 同一执行上下文中的再次求解称“二次自检”，不称独立盲审。需要独立复核时阶段末集中一次进行。小试计时从启动到可交付验收完成，并列核心处理区间；不同题目难度及缺失 token 数据不支持成本/速度改进比率。

- 初次只读入口与本约定；其余引用按需读取。恢复任务先读 state，不重读聊天和整库。
- 只取当前来源及相邻上下文，检索相关概念，不把所有 PDF/OCR/旧答案反复装入上下文。
- 题干解答单份权威存储；模板/目录/链接尽量确定性生成，改动只更新受影响项。
- 已渲染页与已核对转写缓存复用，仅放大疑点区域。交接提供入口、范围、状态和当前来源，不传完整聊天历史；不能把全历史交接称为无上下文盲测。
- 同一知识点的题目集中链接，不为每道题复制一份同义知识点。通用检查程序先探测可用依赖，再批量检查变更文件；阶段末做一次全库检查。检查通过后无新改动不重复运行。
- 经济执行者提交疑点与证据，复核者只接相关来源和必要上下文；全量审查仍逐项覆盖，不能偷换成抽样。
- 完成本批后记录结果不复述全文；不要为了节省 token 删除来源定位、适用条件和未解决项。

这是减少重复消耗的方法，没有跨模型的最低 token 或固定成本保证。

每阶段分别记录核心处理窗口与端到端交付窗口、完成条目数、核源/生成/复核/检查耗时（可获得才填）、工具调用数量及token用量。模型用量只取执行工具实际返回值，不可用就写null；文件时间只能作为活动区间，不能冒充模型推理耗时或token统计。若同步、附件补齐或人工收尾超过核心处理窗口，报告必须单列，不能把核心窗口写成总用时。
