# 学习笔记整理准则

版本：2026-11-10

目标是让读者沿正文理解概念、重建关键推导，并判断何时使用结论。简洁来自去除重复与整理话术，不能靠省掉理解所需的内容实现。本文是本仓库笔记编写、重写和复核的统一准则；专项文档补充操作方法，发生冲突时按本文处理。用户当前的明确要求优先。

## 整体约束

### 先确定任务与实际范围

- 区分讲解、改稿、复核和发布。更新准则不自动启动整库重写，讲解问题不自动授权修改笔记。
- 结合本轮及前文确定范围，先核实实际库路径、章节、卡片与版本。用户说“从某章某篇往后”时，逐项列清包含的后续章节，不能自行缩成该章剩余几篇。
- 已指定课程、章节或卡片时按该范围处理；未限定且上下文没有明确对象的“检查知识库”，默认全库盘点，覆盖知识卡、题卡、题解、教材正文、目录、索引，另列原始材料和后台记录。抽样不算全查。
- 多文件任务维护一份库外 TaskList，记录范围、进度、证据和未决问题。简单编辑不搭复杂审批流程；已获授权的工作继续完成。
- 用户要求样稿确认后推广时，先完成指定样稿，等待真实反馈；后续若已明确授权推广则直接执行，不重复索取许可。样稿完成与用户验收分别记录。

### 来源和事实先于表达

先读现有知识库中相关内容与已认可的代表卡，再定位教材、课件、原题或其他可靠原件。旧稿、OCR、搜索命中和历史完成记录都是线索，不是当前内容正确的证明。

定义、条件、公式、图形和题意有疑点时回原页；关键变形独立复算。区分理论结论、近似公式、题给表值、数值复算、仿真与实测。原资料有错误时保留原题身份，说明具体差异；不能无声改题，也不能照抄错误。

来源版本、页码、时间戳、处理记录放私有后台，默认不占正文或属性区。影响结论的模型、假设、缺损和限制属于知识，必须就地说清。实验报告的交付措辞不能被泛化为“笔记可以隐去适用条件”。

### 保全有效内容，按需要补齐

“优化、重构、写清楚”默认保全有效定义、条件、推导、原有来源例题、图表、辨析与方法。先读整卡及涉及的图，再记录原内容在新稿中的去向；错误修正、重复合并和移位都有理由。内容已经合适就保留，不以改动数量证明工作量。

不新增自编例题、自编练习、自测或配套答案，不以“每篇一个短例”补栏目。教材、课件及用户已有原题按需要保留或链接复用。旧稿中的无来源自编题不因“保全”成为必须保留的内容；在已授权改稿范围内核实身份后处理并留记录。用户另行明确要求出题时才按该请求执行，标明题目身份。

必要的机制解释、符号推导和原图说明仍要补足；不得把禁止自编题误解成只许摘抄原句，也不能借“直觉演示”绕过要求插入新数值题。

## 内容怎样连续展开

### 先让读者知道研究的是什么

开篇直接说明研究对象和要解决的问题。新概念在第一次使用前讲清：它是什么、作用于哪个对象、在哪个环节起作用、为什么需要它。只补足本篇必需的先修含义，再给延伸链接，不能把核心解释全部交给链接。

定义不能循环解释，也不能只是换一个术语。首次出现的符号说明含义、下标、量纲及所在位置或时刻；概率量说明对应事件。相近概念只重点比较会影响理解或选法的区别。

### 先讲完整对象，再作横向比较

多个同类方法或制式，初学正文优先按对象组织：讲通一个对象的含义、机制、模型、结果和使用条件，再讲下一个，最后比较共性与差异。避免先列全部定义、再列全部性质、最后集中列全部公式，让读者自己拼接。

这一原则不要求每个对象机械复制相同栏目。已讲清的共同原理只讲一次，后文简短回接并解释自身变化；确实共享的完整推导可复用，不能因此省去每个分支的参数、结果与边界。用户明确要横向速查时按比较维度组织。

基础、常见情形先讲通，再引入条件变化或一般形式。用户需要常见情况时，不用参数繁多的任意情形推导增加记忆负担；用户要求完整推导时则保留必要分支。没有通用简式或不适用的组合，解释原因，不为凑齐表格造公式。

### 段落之间要有理由

通常沿“问题 → 对象与模型 → 机制 → 公式推导 → 用法与条件变化”展开，但不用把这条路线做成每篇固定的标题模板。

一个段落解决一个主要理解问题。引入新方法时说明原方法哪里不足、改变了什么、解决什么、付出什么代价；并列分支没有因果关系就直接并列。教学先后不等于实际处理流程，正文、框图与描述须一致。

转折应说明关系：因为哪个条件所以得到哪一步；为解决哪个问题才引入下一个量。仅加“首先、其次、然后”不能修复逻辑断层。结论在本段落地，再进入下一段，避免读者反复跨页寻找必要解释。

### 详略按理解障碍分配

详写首次建立联系的步骤：现象怎样变成模型、事件怎样变成不等式、积分边界从哪里来、为何加权或求导、采用哪个近似。公式之间有推理跳跃时补足依据，不能用“显然、代入即得”掩盖。

已解释的定义、重复代数和可直接代入的特例可以略写。表格只归纳已讲清的内容，不承担首次教学。没有统一字数、段数或栏目数量要求。

用户说“不懂”时，定位其不认识的对象或断掉的推理，从更低的起点重新连接；不能只在旧稿开头添一句定义，也不能以继续堆公式代替解释。其反馈应带动本卡同类位置及相关公式、图表一起核对。

## 公式要能选、能算、能判断边界

公式附近说明所求量、可用条件、输入量及其口径。条件不能只藏在页首或链接后面；比较优劣、倍数和性能差异之前，先统一比较基准。

同名量不一定同义。输入与输出、峰值与平均值、单边与双边、频率与角频率、线性量与分贝量等差别，会影响系数与结果。换记号时显式换算，同篇符号保持一致；不同来源的公式不能只因名称相同就拼在一起。

讲解原题时沿以下过程走通，不强制另起六个标题：

1. 核清完整条件、问题、图形和题号。
2. 判断对象及工作方式，说明题目哪些条件决定采用该模型。
3. 统一符号、单位和已知量的定义。
4. 给出选法理由，再逐步推导与代入。
5. 解释结果，并用量纲、数量级、边界或回代核查。
6. 说明哪些条件改变后需要换公式。

“什么情况下用什么公式”的速查，应写成条件与操作的对应关系，不能只列公式名称。原题条件缺失时说清缺口，不猜补。选项字母、按钮顺序与选项内文字可能不一致，核对实际选项内容；理论解答与平台判分证据分别处理。

## 排版服务于阅读

### 标题、自然段和并列条目各有用途

知识卡需要让读者一眼看出对象、关键变化和解释的层次。适合的地方先用一行加粗的核心判断，下一段用常规字重解释它的含义、理由与条件；解释段可用两个全角空格起首（`　　`），在实际客户端确认缩进效果。对同类对象分别这样展开，不把整段教材式叙述或每一句话都加粗。连续推导仍保持完整自然段，不为了视觉整齐切断因果关系。这是排版手段，不是每卡必须套用的模板。

并列的限制、性质、改进或待回答问题，用引导句和 Markdown 列表逐条呈现。条目本身要有足够语义，避免只剩孤立关键词；解释与列表之间留空行，检查实际阅读视图。

- 知识标题不加装饰性序号；文件排序号、原题号和确有定位用途的原教材编号可以保留。不要为了去标题序号随意改文件名或破坏锚点。
- 标题按真实包含关系分级，标题承诺的对象与范围在正文逐一覆盖。短提示可加粗，不必再建一层标题。
- 连续解释、机制和推导用自然段；并列性质、结论、特点和条件先给对应标题，下方逐条换行缩进，直接写内容，不写“性质一、性质二”。
- 默认用普通 Markdown 无序列表实现条目缩进，不用裸 Tab 或四个空格把正文变成代码块；具体客户端显示仍需验证。
- 有明确先后关系的操作步骤或解题过程可以编号；这不等于给知识标题编号。避免过深嵌套、碎片化短句和整页加粗。
- 表格用于少量维度的横向比较。长段推导和大段说明放回正文，不为了整齐制造宽表或重复图文表三份内容。

### 图形与公式必须实际可读

原图若已清楚展示发送、接收或处理流程，直接在相应位置引用图，并用简短文字指出入口、关键分支和结论。不要把整张图重写成横贯一段的箭头串；图外确有重要条件、变化或易误读处，再补足说明。引用前实际查看原图与显示效果。

实际打开涉及的图再决定保留、裁剪或撤下展示。电路、波形、频谱、分布、几何和处理路径中有独有信息就保留；纯文字已完整转写且没有额外信息的截图可不展示，原件仍留档。

图放在相关解释附近，保留完整坐标、箭头、图例、单位及必要标注；说明该从哪里读、关键变化是什么、与哪一公式相对应，不逐字抄图。不要使用依赖空格对齐的 ASCII 波形。

需跨设备使用的图片存于实际知识库内，用可移植的相对路径或库内链接。核对真实文件名、大小写及扩展名，显示别名不代替物理文件名。本机文件存在、同步上传成功和接收端能显示是三件事，分别验证。

数学在支持的正文中使用 `$...$` 与 `$$...$$`；含数学的表用 Markdown 单元格，绝对值使用 `\lvert...\rvert` 等不会拆列的写法。不要把 LaTeX 混入 HTML 表格或用代码反引号代替公式。聊天、浏览器和 Obsidian 的渲染证据不能互相冒充；用户报告未渲染时须检查实际载体。

## 从接手到交付

1. **盘点与定位**：确认目标、当前版本和范围，先读已有有效样稿及相关来源。对话中的明确纠正优先于旧模板；助手自拟做法不自动算用户已认可。
2. **保全与规划**：批量修改先备份。记录知识点与图表的去向，按对象和先修关系排好主线；先确定哪里需要补解释，再写稿。
3. **编写与即时核对**：先核事实、条件和推导，再优化表达。通用知识与完整题解各有权威位置，保留必要关联；沿用可用目录和题答布局，不为套规范重复建卡。
4. **整卡连读**：从读者起点读到结尾，检查新术语是否先解释、每一步能否接上、标题是否兑现、常见情况是否能找到；对照原稿检查有效内容未丢失。
5. **分层验收**：按下表记录实际完成范围。检查和修正全部改动；若任务是全量复核，还须审读范围内未改的文件。抽样只能报告抽样结果。
6. **发布与同步**：写回前比较目标文件与起始版本，出现他人新改动先合并，不用旧快照覆盖。按授权发布后回读文件和远端版本；只同步通用工作流到公开仓库，私人资料与会话不外发。

| 验收层 | 检查什么 | 不能据此声称什么 |
| --- | --- | --- |
| 内容保全 | 原知识点、条件、图表的去向与修改理由 | 字数相近不证明完整 |
| 专业与来源 | 实读范围、原页原图、关键推导及数值 | 检索或 OCR 命中不证明核过原图 |
| 可读性与连贯性 | 概念落点、前后承接、详略、对象覆盖与选法依据 | 标题齐全不证明可以自学 |
| 文件与渲染 | 链接、附件、表格、数学与实际显示 | 静态扫描不证明公式语义正确 |
| 发布与多端 | 备份、写回、版本及接收端实际显示 | 哈希一致不证明内容审读或客户端验收 |
| 学习反馈 | 用户实际阅读、复述或已有题的独立作答 | 助手认为清晰不证明用户已掌握 |

学习反馈是改进依据，不是每次交付都必须要求用户做测验。未做的验收层如实写在交付说明与后台，不制造完成记录，也不把待核知识写成无条件结论。

## 多个 AI 使用同一套规则

维护一份统一准则，各客户端入口只保留必要摘要、版本与正文位置。更新时同时处理旧入口中的冲突规则，不能仅在文件尾再追加一段；不改与笔记任务无关的权限、人格或项目约定。

同步前备份并核对目标文件的新变化，同步后逐文件回读。分别报告“文件已更新”“内容一致”“客户端已加载”“实际执行已验收”；没有运行证据时，不宣称已有会话即时生效。需要重新加载时只提示开启新会话或在原会话明确重读准则，不擅自重启或打断正在执行的任务。
