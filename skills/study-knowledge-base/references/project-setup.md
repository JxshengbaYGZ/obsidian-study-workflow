# 项目配置与模板

开始时确认来源目录、输出目录、目标软件、已有排版样例及实际范围。文件夹名称可以沿用用户习惯；不要硬编码个人绝对路径。脚本缺失时建立适合当前项目的检查方法，不声称运行了不存在的门禁。

建议分开存放：笔记/主题、题目/主题、原始资料、整理记录。批量大小取决于材料长度与风险，先用一组完整样例确认。

## 知识点模板

```markdown
# 概念名称
## 定义与成立条件
## 方法与使用边界
## 例题与应用
每个链接旁说明关系。
## 来源
具体文件、页码或时间戳。
```

## 题卡模板

```markdown
# 题意标题
## 题目
完整条件及选项。
> [!example]- 标准解答
> 独立推导与最终结果；有来源缺陷则先说明。
## 方法与易错点
## 原题与原作答
对应裁图与位置；自编题不造原图。
## 相关知识
知识点链接与关系解释。
```

折叠解答采用目标笔记软件实际支持且验证可用的方式。没有原题截图时，不生成空图片链接。

目标为Obsidian且没有其他已确认样例时，采用 `> [!example]- 标准解答` callout，并为内部每行加 `>`，不要自行换成HTML details。公式后的句号并入相邻正文或省略，避免句号独占一个段落。KaTeX语法通过只验公式，不验外层折叠与阅读版式。

## 技巧记录

数学结构和知识点合并判据见 [Terra执行说明](terra-review.md) 的“数学结构与概念分类门禁”；即使使用其他模型，该判据同样适用。沿用目标软件已经验证的样例，不在折叠块上再重复同名标题。

名称、来源原文与位置、对应知识点、具体动作、适用条件、失效边界、具体短例、整理者补充、来源/公式/逻辑/反例/短例/重复检查。无独立技巧或重复均说明原因，不凑数量。
