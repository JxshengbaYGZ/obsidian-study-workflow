# 按内容选择排版

先读[统一准则](note-standard.md)。沿用已有可用目录与题答布局，下面仅演示语法，不是每篇要填满的栏目。

## 知识卡

```markdown
# 概念名称

先解释研究对象和问题，再沿机制、模型与推导连续展开。

**核心变化：用一句话说清对象发生了什么。**

　　这里用常规字重解释它为什么成立、解决了什么问题，以及适用条件。

## 性质与适用条件

- 一条独立性质及成立条件。
- 另一条独立性质及成立条件。
```

连续解释用自然段，不把每句都变成条目。知识标题不加装饰序号；教材转写中有定位用途的原编号及原题号保留，已有文件排序号不随意改动。标题父子层级真实，修改标题时检查锚点。

加粗概括和缩进说明只在有助于阅读的位置使用。现成流程图若足够清楚，就引用图并指出读图重点，不逐箭头转写。

公式表采用 Markdown，单元格内用 `$...$`，绝对值用 `\lvert...\rvert` 避免拆列。不在 HTML 表格中混写 LaTeX；复杂表图若需要保留，只用一份完整且可读的呈现。

不新增自编例题、练习或自测，不建立空栏目。来源已有题目按需复用，深层推导放正文，不塞入宽表。

## 题卡

```markdown
# 原题编号与题意标题

完整条件、问题与选项；题意依赖图形时放必要局部图。

> [!example]- 解答
> 先说明选法理由，再给关键推导、代入、结果与核查。
```

已有题解分文件时继续使用，避免重复保存同一权威解答。折叠语法须在目标客户端核验，不把 Obsidian 语法在其他载体的普通文字显示误报为折叠成功。

## 后台记录

来源、页码、原件与改动证据记在私有记录。正文保留影响理解与使用的条件和具体疑点；不放“已核对”“编辑补充”等过程标签。
