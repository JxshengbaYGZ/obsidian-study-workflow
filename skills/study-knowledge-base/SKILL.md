# 长期知识库

这是「知识库一侧」：面向考研复习、大学期末与课程长期使用，把笔记、讲义、字幕与题集整理成按概念组织的知识点卡、题卡与独立解答。只依赖本技能、用户材料和执行工具，不依赖历史聊天。

需要把扫描教材（PDF 整页图 + OCR 文字层）变成可检索、可回查页码的正文与知识点卡时，用仓库里的教材一侧技能：`skills/textbook-library`（独立文件夹，单独复制后按其 SKILL.md 执行）。两侧用「教材对照」回链连起来，页码一律用 PDF 物理页。

## 执行

需要从头落地一个章节或可恢复批次时，先读 [正式批处理](references/portable-workflow.md)：它提供完整输入、构建、独立复核、排版和增量发布协议。核心脚本 `scripts/kb.py` 统一执行门禁；正文由 AI 按来源编写，程序负责固定结构和链接。单纯审查已有库可沿用下列按需规则，不必迁移整个旧库。

1. **启动一次**：读 [执行约定](references/execution.md)，检查材料和图像读取能力；确定输出目录，建立来源清单、知识点提纲和进度文件。不把缺材料误当缺知识。
2. **每批按需读**：只读进度、当前完整来源单元、相关知识点与题卡。首次套用 [模板](references/project-setup.md)；遇来源或专业条件争议才读 [审查规则](references/review.md)；需要换执行者才读 [分工](references/model-routing.md)。
3. **先核源再写**：知识点按概念而非页拆分，题目独立、选项完整。原题与原作答裁图逐题定位；无原作答如实写明。缺陷不静默修成标准题，自编题与补充内容明确标识。
4. **随写自检**：主解匹配材料章节与前置知识，关键变形写明依据，新记号先定义；检查条件和具体算例，复算针对最可能出错的步骤。独立复核在阶段末集中进行，来源矛盾等局部阻塞先隔离。自检通过不等于独立复核通过。
5. **增量落盘**：题卡保存一份权威题干与解答，知识点用带关系说明的链接引用；已有重复展示同步修正。每批更新台账和下一步，不重写整库。
6. **阶段收尾**：对照完整来源清单集中复核该阶段条目，再统一同步和检查。审查者改动也需复检公式与证据状态。分别报告已核定、待补证、未审查；抽样不是全量复核，格式通过不是内容正确。

已有库用于新题或实际问题时，先检索相关知识点、条件和例题，再独立求解；事后审查用到的权威笔记、题卡与导航。先补足错误、来源和边界，再压缩重复表达；没有实质改进时保留原文。大型库按常见问题建导航，题目与解答分开并互相回链，结构覆盖不能冒充逐题语义复核。方法见仓库 `docs/workflow.md`；公开示例只使用虚构材料。

台账格式及可选检查工具见 [记录规则](references/records-and-quality.md)。需要查看最终成品时读 [电路学习小样](references/example/README.md)；它是自编验收示例，不是用户原稿。

将清晰的小批资料交给 Terra 等经济模型时，额外使用 [Terra 自审记录](references/terra-review.md)。

省略重复解释和重复读取，不省略核源与独立验证。无法直接看图时先处理可读资料，并点明具体缺口；不声称只靠本仓库就能识别不存在或不可读的原稿。
